# Claude Code Configuration

Documents all Claude Code customizations, their locations, and purposes. Read this before modifying any Claude config; update it after any change that adds, removes, or repurposes a component.

## Source of truth

Everything lives in the dotfiles repo and is stow-linked into `$HOME` (via `stow_check` / `stow_do` from `~/.dots`):

```
~/.dots/.claude/                    # Claude-specific package → stow-linked into ~/.claude/
├── README.md                       # this file
├── settings.json                   # CANONICAL COPY — deliberately NOT stow-linked (see below)
├── keybindings.json                # keyboard shortcuts
├── statusline-command.sh           # starship-based status line
├── rules/                          # → ~/.claude/rules (always-loaded global rules)
│   ├── claude-config.md            # config-maintenance + correction-routing policy (Claude-only)
│   ├── multiline-and-oneline.md    # paired multiline + one-line REPL artifacts (Claude-only)
│   ├── abbreviations.md            # symlink → ../../.ai/rules/abbreviations.md (shared)
│   ├── agent-ops.md                # symlink → ../../.ai/rules/agent-ops.md (shared)
│   ├── placeholder-stubs.md        # symlink → ../../.ai/rules/placeholder-stubs.md (shared)
│   └── ruby-general.md             # symlink → ../../.ai/rules/ruby-general.md (shared)
├── hooks/                          # → ~/.claude/hooks
│   ├── block-shell-substitution.sh # PreToolUse(Bash): ask before $(...), backticks, <(...), >(...)
```

## Key mechanisms

### settings.json (canonical copy, not linked)

Claude Code rewrites `~/.claude/settings.json` itself (permission grants, `/model`), so it is excluded from stow (`.stow-local-ignore`). The tracked canonical copy is `~/.dots/.claude/settings.json`. After a deliberate settings change, copy the live file over the canonical one; the `dots-commit` skill diffs them and flags drift.

Highlights: read-only Bash/git allowlist, `find`-mutation ask-rules, `additionalDirectories` for `/Volumes/dev/_tasks` + `/tmp`, both PreToolUse hooks, statusline, skill overrides.

### Hooks (deterministic enforcement > prose rules)

- `block-shell-substitution.sh` — asks before any Bash command containing `$(...)`, backticks, `<(...)`, `>(...)`. Skips in auto permission modes. Requires `jq`.
- `commit-gate.sh` — when a Bash command runs `git commit`, asks if the staged diff still adds the stub marker from `placeholder-stubs.md` (`SHOULD BE HANDLED/REMOVED BEFORE MERGE`). Intentionally active in ALL permission modes — deferring a stub must be an explicit user decision.

Both are registered in `settings.json` under `hooks.PreToolUse` (matcher `Bash`) via their `~/.claude/hooks/` paths, which resolve through the stow link.

### Pi rule generation

Pi loads `~/.pi/agent/AGENTS.md` → symlink to `~/.ai/rules/pi-global.md`, which is GENERATED by:

```bash
~/.dots/.ai/bin/generate-pi-global
```

Sources, in order: `ruby-general.md`, `agent-ops.md`, `pi-only.md`, `placeholder-stubs.md`, `abbreviations.md`. Claude-only rules (`claude-config.md`, `multiline-and-oneline.md`) are not sources. After editing any source rule, rerun the generator.

### Project-specific rules (version-controlled, outside project repos)

Pattern: rule content lives in `~/.dots/.ai/rules/<project>.md`; each project checkout gets a one-line gitignored pointer file `CLAUDE.local.md` containing `@~/.ai/rules/<project>.md`. `CLAUDE.local.md` is ignored globally via `~/.gitignore_global` (wired as `core.excludesFile`). Current: `gtm.md`, pointed to from `/Volumes/dev/projects/shaka/gtm/{1st,2nd,3rd}/`.

### Correction-routing policy

When a mistake or new guidance needs a home, route it to the narrowest mechanism that fixes it:

1. **Hook** — if it is mechanically checkable (strongest: cannot be forgotten).
2. **Skill / skill reference** — if it only matters inside one workflow (e.g. review lessons → `super-review/references/past-findings.md`).
3. **Project rules** (`.ai/rules/<project>.md`) — if project-specific.
4. **Always-loaded global rules** — last resort, only for cross-cutting hard constraints; include the why.

Do not add global rules for situations a skill or hook already covers. Keep always-loaded rules to non-obvious constraints; trust model judgment for standard practice.

## Big skills use progressive disclosure

`super-review` and `autowork` keep a short `SKILL.md` spine plus `references/*.md` files read only at the phase that needs them. Follow the same pattern for any skill whose SKILL.md grows past ~200 lines.
